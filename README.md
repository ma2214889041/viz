# VIZ

一个交互式可视化博客：每篇文章围绕一个具体问题，给出可以亲手操作的模型。

根目录是博客首页，每个子目录是一篇可以独立阅读、操作和分享的可视化文章。

每篇文章都是**一个自包含的 HTML 文件**：没有前端框架、没有 CDN、没有服务端状态。所有交互都在读者的浏览器里运行。站点构建负责验证文章、复制静态文件并生成文章清单、Sitemap 与 RSS。

## 画面主角（舞台）

挂谷篇与玻尔兹曼篇里，每一章都要声明**这会儿画面的主角是谁**。多数章节是三维场景；但有几章的论证本身就是一张图——「有没有一个只往一个方向走的量」，答案就是 H 曲线的形状。那种章节里，图会走到画面正中并放大到原来侧栏卡片的 8 倍面积，三维退成还在跑的背景（图是从它身上量出来的，不能停）。

写法是在章节对象上加一个 `st`：

```js
st:'h'                    // 一进这章就把 H 曲线放到画面正中
st:['3d','mb',5200]       // 先看三维，5.2 秒后直方图接棒
```

约定与守卫（全部由 `tests/*-model.mjs` 拦住）：

- `st` 指的图必须在这一章的 `CHARTS` 列表里，否则 `setStage` 会静默退回三维，正文就会指着一个空位说「看这里」
- 正文里的看图按钮同理，要写明目标：`data-open-charts="mb"`（`"3d"` 表示切回三维场景）。不写目标就退回旧行为（在角落里闪一下）
- 自动换主角不得早于 3 秒，否则读者还在读第一段画面就被换掉；读者一旦自己切过，这一章就不再自动改
- 舞台和镜头共用 `freeRect()`（那块没有被面板盖住的画面），所以它永远压不到讲解面板和读数上；空地窄于 330px 时不上台，保持原来的行为
- 图表的绘制代码里不许写死宽高，一律问当前容器要（`chartBox()`）：同一个 `<section>` 节点会被搬到舞台上，放大时字号、内边距、线宽都要跟着长（`chartScale()`），而不是把小图拉伸

### 镜头也要落在空地里

`freeRect()` 里的可见性判断原本写的是 `el.offsetParent !== null`。三块面板全是 `position:fixed`，而 `offsetParent` 对 fixed 元素一律返回 `null` —— 于是这个判断恒为 false，函数一直在走「什么都没挡住」的兜底分支。也就是说它从来没生效过。

改对之后还剩一半问题：透视矩阵的 `ox/oy` 只是把画面**平移**到空地中心，内容的**大小**一点没变，所以东西仍然可能大到伸进面板底下、或者在手机上伸出屏幕。挂谷篇的 `fitDist()` 补上了后一半（只往外推、不往里拉，上限 2.4 倍，读者自己滚过滚轮之后不插手）。测试逐章 × 四种视口尺寸扫一遍，确认每一章的内容都落在空地里 —— 去掉这条规则，它会当场报出第 7 章的方向球和手机上第 1 章扫出的球。

## 加一篇新文章

1. 建文件夹 `your-work/`，放入自包含的 `index.html`
2. 按现有格式增加 `work.json`
3. 在 `scripts/build.mjs` 的 `workDirs` 中登记目录
4. 在首页文章列表中增加对应入口，并更新文章计数
5. 在 `tests/publication-audit.mjs` 的 `works` 中登记

### 收录标准

主题不限于数学——物理、生物、经济、工程、社会系统都可以。唯一的门槛是**这个题目真的需要可视化**：

> 读者调节一个连续参数，模型每帧重算，然后他看到一个静态图配文字给不了的因果结果。

`publication-audit` 会强制这一点：文章必须有 `<canvas>`、`requestAnimationFrame`，以及至少一个连续输入或音频输出。

如果一个题目的核心是论证、史料或概念辨析，那它是一篇好文章，但不是这个站点的形式——不要用按钮和折叠块把散文伪装成交互。

## 部署

正式地址：<https://viz.gopromp.com>

正式环境使用 Cloudflare Workers Static Assets，配置文件为 `wrangler.jsonc`。Worker 只负责给 HTML 导航加 `no-store`，避免发布后读到旧页面；没有其他服务端逻辑。运行 `npm run deploy` 会完成构建、类型检查、测试并更新正式站点。

同时保留 Cloudflare Pages 项目 `viz` 作为备用部署与预览地址；构建命令为 `npm run build`，输出目录为 `dist`。

## 关于内容的准确性

演示里出现的数值都是实时算出来的，不是写死的动画。做的时候用独立的 Node 脚本交叉验证过：

- 挂谷集的体积与 Perron 树递归的独立实现比对，相对误差 < 1e-5
- 12 个方向锥用 6 万个随机方向抽样：覆盖率 100%，而且每个方向**恰好被一个锥覆盖一次**（12 个锥是不重不漏的划分），12 个变换矩阵严格正交
- 方向地图用的兰伯特方位等面积投影经过抽样验证：半球恰好铺满单位圆盘，圆盘内半面积里落着 50.3% 的方向 —— 只有等面积成立，「圆盘填掉多少比例＝覆盖多少方向」这句读法才算数
- 第 7 章声称「层数一路拉满，方向地图一个点都不动」：绘制方向地图的代码不允许引用递归层数，浏览器里实测各层数下逐像素指纹完全相同
- 玻尔兹曼第 8 章的 V 字：同一个混沌低熵初态，往未来推与往过去推的 H 落差之差实测 0.11%–0.18%（三种初态），尾段抖动不到落差的 1%
- 硬球气体的能量守恒到 1e-8（机器精度）；速率分布与麦克斯韦–玻尔兹曼曲线的 L1 偏差落在 √N 散粒噪声量级内
- H 函数在时间反演后的回升幅度、盒维数随尺度的变化，都是实测数据
- 玻尔兹曼双轨实验从同一随机种子重建粒子位置与速度，并比较初态校验码；校验失败时不接受因果结论
- 反应扩散文章固定使用 Dᵤ=1、Dᵥ=0.5、Δt=1 的显式 Euler 更新、3×3 离散拉普拉斯和环形边界；四组预设均用独立脚本运行 8000 步确认不会衰减为空场
- 优化文章的地形族 f = x⁴/4 − κx²/2 + y²/2 + tx 的临界点与 Hessian 特征值均可闭式验证：κ=2 时鞍点特征值恰为 (−2, 1)、极小在 ±√2；高维正定比例由固定种子抽样，d=6 时 4 万次抽样为 0
